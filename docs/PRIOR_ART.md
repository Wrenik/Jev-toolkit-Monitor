# Prior art, attack taxonomies and what each one changed

Research done 2026-11-04 (review round 2) with web search and page fetches. **Read quality is marked per item**: "read" means I fetched and read the page (or the relevant part), "snippet" means I only saw a search summary, usually of a secondary source. Where a number or CVE detail comes only from a secondary source it is labelled so; verify before quoting. None of this code was copied.

## 1. The Claude Code hook contract (what the classic `PreToolUse` route may rely on)

Source: [Claude Code hooks reference](https://code.claude.com/docs/en/hooks) (read: the first third, 100,000 of 286,000 characters, which includes the whole PreToolUse section; later sections not read).

| Fact | Detail | What it means here |
|---|---|---|
| Input (stdin JSON) | `session_id`, `cwd`, `permission_mode`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`; plus `transcript_path`, `prompt_id`, `effort`, and `agent_id`/`agent_type` inside subagents | `hook_main` reads `tool_name`, `tool_input`, `cwd`, `session_id`, `agent_id`: matches |
| Output | JSON on stdout with `hookSpecificOutput.hookEventName = "PreToolUse"`, `permissionDecision` = `allow` \| `deny` \| `ask` \| `defer`, `permissionDecisionReason`, optional `updatedInput` | the monitor emits `deny`/`ask` and a note via `additionalContext`; `defer` and `updatedInput` are unused (it never rewrites calls) |
| Exit codes | 0: JSON applied, no output = no decision. 2: blocking error, stderr is the reason, **JSON is ignored**. Any other code: non-blocking, the call proceeds | the monitor always exits 0 with JSON, so a crash (other code) would proceed: hence `onFailure: "block"` in `hook-snippet` |
| Failure and timeout | a timed-out PreToolUse hook does not block by default; `"onFailure": "block"` blocks on failure or timeout (needs Claude Code v2.1.295 or newer, per the page) | `hook-snippet` sets it; the README should say "v2.1.295+" for the classic route |
| Matchers | exact name, `A\|B` list, `*`/empty for all, anything else is a JavaScript regex; MCP tools are `mcp__<server>__<tool>`; `mcp__memory` alone matches nothing, `mcp__memory__.*` matches a server | **fixed this round**: the snippet's matcher omitted MCP and sub-agent tools; it now ends `...\|WebFetch\|Agent\|Task\|mcp__.*` |
| `if` field | finer filter in permission-rule syntax, e.g. `Bash(rm *)` | not used; the engine decides |
| Events | session, per-turn, tool-loop (`PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolBatch` ...), subagents (`SubagentStart/Stop`), `InstructionsLoaded`, `ConfigChange`, `FileChanged`, worktrees, compaction, MCP elicitation | `PostToolUse` (tool results) and `InstructionsLoaded`/`ConfigChange` are the natural next hooks for the "tool result" and "poisoned rules file read" gaps (not built) |

The mod route uses the mod API (`tool.call`), documented in the generated type definitions; see `docs/AGENT_MONITOR.md` "What the hooks can actually do".

## 2. Attack taxonomies

* **OWASP Top 10 for Agentic Applications 2026** (released 2025-12-09; names read on [Cycode's summary](https://cycode.com/blog/owasp-top-10-agentic-applications/), also [Giskard](https://www.giskard.ai/knowledge/owasp-top-10-for-agentic-application-2026), [Indusface](https://www.indusface.com/learning/owasp-top-10-agentic-ai/); official document not read): ASI01 Agent Goal Hijack, ASI02 Tool Misuse and Exploitation, ASI03 Identity and Privilege Abuse, ASI04 Agentic Supply Chain Vulnerabilities, ASI05 Unexpected Code Execution, ASI06 Memory and Context Poisoning, ASI07 Insecure Inter-Agent Communication, ASI08 Cascading Failures, ASI09 Human-Agent Trust Exploitation, ASI10 Rogue Agents. Used as the spine of held-out set 5 and of the coverage table.
* **MITRE ATLAS** (snippets only: [Startup Defense: AML.T0086](https://www.startupdefense.io/mitre-atlas-techniques/aml-t0086-exfiltration-via-ai-agent-tool-invocation), [case AML.CS0045, Cursor MCP exfiltration](https://www.startupdefense.io/mitre-atlas-case-studies/aml-cs0045-data-exfiltration-via-an-mcp-server-used-by-cursor), [Speakeasy](https://www.speakeasy.com/blog/mitre-atlas-explained)): "Exfiltration via AI Agent Tool Invocation" (the agent's own tool calls are the exfiltration path) is the technique this monitor's `secret-exfil-shape` and the new publish rules target; the Cursor case is a `curl` of credential files to the attacker's host. Technique IDs differ between secondary sources: verify on atlas.mitre.org.
* **Lethal trifecta** (private data + untrusted content + external communication; Simon Willison, June 2025) and Invariant Labs' **toxic agent flow** for the GitHub MCP server (snippets: [DZone](https://dzone.com/articles/mcp-lethal-trifecta), [Invariant](https://invariantlabs.ai/blog/toxic-flow-analysis)): an issue with hidden instructions makes the agent read a private repo and publish it in a public pull request. Changed: publishing commands through allow-listed hosts (`gh gist/issue/pr/release/api`, `aws s3 cp`, `rclone`) are now treated as a way out when a secret is in the same command.

## 3. Incidents and writeups of attacks on coding agents

| Item | What happened (as reported) | Read quality | Effect on the monitor |
|---|---|---|---|
| Rules File Backdoor (Pillar Security, March 2025) | invisible Unicode (zero-width, bidirectional) in `.cursor/rules` / Copilot instruction files steers the assistant ([Hacker News coverage via dev.to summary](https://dev.to/tigranbs/securing-ai-coding-agents-what-idesaster-vulnerabilities-should-you-know-4m81), [decryption digest](https://www.decryptiondigest.com/blog/ai-coding-tool-config-file-backdoor-attack-surface)) | snippet | writing such a file was already high (instruction files); new `hidden-unicode` warns on any written text with invisible/bidi characters. Reading a poisoned file is not seen |
| MCPoison, Cursor CVE-2025-54136 (Check Point) | an approved MCP config is silently changed in a shared repo and runs new commands | snippet (CVSS and fix version from secondary sources) | `.mcp.json` / `~/.claude.json` writes are high; `claude mcp add` and `codex/gemini mcp add` are now high (`agent-config-change`) |
| MCP tool poisoning and rug pulls | instructions hidden in a tool description; a trusted tool updated later ([Martin Fowler's piece](https://www.martinfowler.com/articles/exploring-gen-ai/software-supply-chain-attack-surface.html), snippet) | snippet | **not covered**: the monitor sees calls, not tool descriptions or server updates. MCP *calls* now get path, command and URL rules |
| Claude Code CVE-2025-59536 and CVE-2026-21852 (Check Point; [ITPro](https://www.itpro.com/software/development/claude-code-flaws-left-ai-tool-wide-open-to-hackers-heres-what-developers-need-to-know)) | project `.claude/settings.json` defined hooks that ran, and `ANTHROPIC_BASE_URL` pointed API traffic (with the key) at an attacker, before the trust dialog; reported fixed in v1.0.111 and v2.0.65 | snippet, secondary | writes to `.claude/**` were already high; setting `ANTHROPIC_BASE_URL` (or other `*_BASE_URL`/proxy variables) to an unlisted host now warns (`traffic-redirect`). The attack happens before any tool call: not coverable by a tool-call monitor |
| s1ngularity / Nx npm compromise (Aug 2025; [Snyk](https://snyk.io/blog/weaponizing-ai-coding-agents-for-malware-in-the-nx-malicious-package), [Socket](https://socket.dev/blog/nx-packages-compromised), [Wiz](https://wiz.io/blog/s1ngularity-supply-chain-attack), snippets) | a postinstall script ran installed AI CLIs with permission-bypass flags (`--dangerously-skip-permissions`, `--yolo`, `--trust-all-tools`) to hunt secrets, then published them through `gh` to a new repo | snippet | agent CLIs started with bypass flags are high (`agent-permission-bypass`); `gh repo create`/`gist`/`api` with a secret in the command is high. A dependency's own postinstall is invisible (only the project's own `package.json` scripts are read) |
| Slopsquatting (package names invented by models then registered; [Endor Labs](https://www.endorlabs.com/learn/slopsquatting-when-ai-agents-hallucinate-malicious-packages), snippet) | agents install hallucinated packages without a human noticing | snippet | `typosquat-package` warns on names one edit from a popular package; `unvetted-package-run` on `npx -y`. A hallucinated name that is not near a popular one needs a registry lookup (age, downloads): not built, would need the network |
| Shai-Hulud style npm worms | stolen tokens republish infected packages | snippet ([InfoQ](https://www.infoq.com/news/2025/10/npm-s1ngularity-shai-hulud)) | `npm publish`/`twine upload`/`cargo publish` warn (`publish-package`); token reads are `credential-store-read` |
| Auto-mode and approval fatigue ([Anthropic engineering](https://anthropic.com/engineering/claude-code-auto-mode), first part read in round 1) | people approve ~all prompts | secondary figures | unchanged: monitor mode first |

## 5. What the research changed, in one list

1. MCP and sub-agent calls were the largest hole (0/5 of the first-run MCP scenarios): they now get path, command and URL rules by argument key, plus a heuristic on sub-agent briefs.
2. Publishing through an allow-listed host is the shape the lethal-trifecta writeups use; a host allow-list cannot see it, so it is judged by command plus secret.
3. Scripts the command line hides (`python x.py`, `./x.sh`, `npm run`, `make`) were the second hole (0/9): they are read and analysed when they exist on disk.
4. Hidden characters, CI pipeline files, redirecting variables, agent CLIs with their safety off, credential stores, typosquats, local-account changes and destructive remote operations were added as generic rules, not as lists of the scenarios that exposed them.
5. Left alone on purpose: tool-result inspection and tool-description scanning (different hooks), registry lookups, taint tracking across calls.
